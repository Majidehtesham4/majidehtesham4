# ERP-VERON (ERPNext ایرانی، iran_erp)

**ERP-VERON** نرم‌افزار مالی و بازرگانی فارسی بر پایه‌ی ERPNext و Frappe (هر دو با مجوز GPL-3.0) است. نام، لوگو و
متن‌های رابط کاربری ERP-VERON هستند؛ هسته‌ی ERPNext دست‌نخورده می‌ماند.

بومی‌سازی ERPNext نسخه ۱۶ برای ایران، به‌صورت یک اپ جدا (`iran_erp`) که روی ERPNext نصب می‌شود
و به هسته‌ی ERPNext دست نمی‌زند؛ بنابراین ارتقای ERPNext ساده می‌ماند.

## نصب روی سرور (با Docker)

پیش‌نیاز: یک سرور لینوکس با حداقل ۴ گیگ رم و Docker.

```bash
git clone https://github.com/majidehtesham4/majidehtesham4.git
cd majidehtesham4/erpnext-iran

# ساخت ایمیج ERPNext + iran_erp
docker build -t iran-erp:latest .

# تنظیم رمزها
cd deploy
cp .env.example .env
nano .env        # ADMIN_PASSWORD و DB_ROOT_PASSWORD را عوض کنید

# اجرا
docker compose up -d
```

ساخت سایت اول بار چند دقیقه طول می‌کشد (`docker compose logs -f create-site`).
بعد از آن سیستم روی `http://IP-سرور:8080` در دسترس است. نام کاربری `Administrator` و رمز همان
`ADMIN_PASSWORD` است. در ویزارد اولیه زبان «فارسی»، کشور «Iran» و منطقه‌ی زمانی `Asia/Tehran` را انتخاب کنید.

ساخت سال مالی شمسی (مثلاً ۱۴۰۵) پس از ویزارد:

```bash
docker compose exec backend bench --site frontend execute \
  iran_erp.api.create_jalali_fiscal_year --kwargs '{"jalali_year": 1405, "company": "نام شرکت"}'
```

### شروع از صفر (پاک کردن همه‌چیز)

همه‌ی داده‌ها (پایگاه داده، فایل‌ها و تنظیمات سایت) پاک می‌شوند و سایت تازه ساخته می‌شود. بعد یک دستور، کار ویزارد
اولیه را با انتخاب‌های ایرانی (فارسی، Iran، Asia/Tehran، ریال، کدینگ حسابداری ایران، سال مالی شمسی جاری) انجام
می‌دهد و داده‌ی نمونه‌ی نمایشگاه خودرو را می‌سازد:

```bash
cd deploy
docker compose down -v                 # همه‌ی داده‌ها پاک می‌شود و برنمی‌گردد
docker compose up -d
docker compose logs -f create-site     # تا ساخت سایت تمام شود
docker compose exec backend bench --site frontend execute iran_erp.fresh_start.run
```

با `-e IRAN_COMPANY=<نام> -e IRAN_DEMO=1` بعد از `exec` نام شرکت و بارگذاری داده‌ی نمونه‌ی نمایشگاه تعیین می‌شود.

روی ویندوز همه‌ی این مراحل با یک اسکریپت انجام می‌شود؛ اسکریپت حجم‌هایی را هم که `down -v` نتوانسته پاک کند
(چون کانتینری هنوز از آن‌ها استفاده می‌کرد) پاک می‌کند:

```powershell
cd deploy
powershell -ExecutionPolicy Bypass -File .\reset.ps1
```

### محیط جدا برای هر کسب‌وکار

هر کسب‌وکار می‌تواند سایت و پایگاه داده‌ی خودش را داشته باشد، روی آدرس `http://<نام>.localhost:8080` (مرورگر هر
آدرس `*.localhost` را به همین کامپیوتر می‌فرستد و نیازی به تغییر فایل hosts نیست). سایت اصلی روی
`http://localhost:8080` دست نمی‌خورد. نام فقط حروف کوچک انگلیسی، عدد و خط تیره است:

```powershell
cd deploy
powershell -ExecutionPolicy Bypass -File .\business.ps1 new shop       # http://shop.localhost:8080
powershell -ExecutionPolicy Bypass -File .\business.ps1 demo shop      # داده‌ی نمونه‌ی نمایشگاه خودرو
powershell -ExecutionPolicy Bypass -File .\business.ps1 list
powershell -ExecutionPolicy Bypass -File .\business.ps1 open shop      # ورود به‌عنوان مدیرِ همان محیط، بدون رمز
powershell -ExecutionPolicy Bypass -File .\business.ps1 reset shop     # حذف همه و ساخت دوباره
powershell -ExecutionPolicy Bypass -File .\business.ps1 remove shop
```

اولین ورود به هر محیط تازه «راه‌اندازی آسان» را باز می‌کند تا نوع کسب‌وکار و امکانات لازم انتخاب شود و برنامه بر همان
اساس چیده شود: صفحه‌ی اصلی فقط آیکون بخش‌هایی را نشان می‌دهد که آن کسب‌وکار لازم دارد (`iran_erp/business/visibility.py`؛
مثلاً نمایشگاه خودرو: نمایشگاه، حسابداری، گزارش‌های مالی و چک‌ها؛ فروشگاه: فروش، خرید، موجودی و حسابداری). بخش‌های
پنهان از جستجو یا با آدرسشان باز می‌شوند. نمایشگاه خودرو بعد از ورود با داشبورد خودش باز می‌شود.

داده‌ی نمونه‌ی هر محیط مال همان نوع کسب‌وکار است (نمایشگاه خودرو یا داده‌ی عمومی فروشگاه/تولید): با
`business.ps1 demo <نام>` یا در برنامه «تنظیمات ایرانی» ← «داده‌ی نمونه» ← «ساخت داده‌ی نمونه».

### پنل مشتری‌ها و بروزرسانی یک‌جا

سایت اصلی (`http://localhost:8080`) پنل صاحب سیستم است: آیکون **«پنل مشتری‌ها»** (`/desk/iran-owner-panel`، فقط
برای مدیر سیستم و فقط روی سایت اصلی) همه‌ی محیط‌های کسب‌وکار این سرور را با نام، نوع کسب‌وکار، تعداد کاربر، آخرین
فعالیت و وضعیت نسخه («به‌روز» یا «نیاز به بروزرسانی») نشان می‌دهد. دکمه‌ی «باز کردن» صفحه‌ی ورود همان محیط را باز
می‌کند؛ برای ورود بدون رمز به‌عنوان مدیرِ یک محیط (برای درست کردن داده‌هایش) روی سرور
`business.ps1 open <نام>` را بزنید (ورود یک‌باره‌ی خود فرپی). دکمه‌ی «بروزرسانی» کنار هر محیط و «بروزرسانی همه»
بالای صفحه، پایگاه داده‌ی آن محیط‌ها را با نسخه‌ی فعلی برنامه هماهنگ می‌کنند (`bench migrate`، در پس‌زمینه) و
خطای هر کدام همان‌جا نمایش داده می‌شود.

**بروزرسانی همه‌ی مشتری‌ها با یک دستور:** نسخه‌ی تازه را از GitHub می‌گیرد، می‌سازد، کانتینرها را با آن بالا می‌آورد و
سایت اصلی و همه‌ی محیط‌ها را بروزرسانی می‌کند:

```powershell
cd D:\majidehtesham4\erpnext-iran\deploy
powershell -ExecutionPolicy Bypass -File .\update.ps1
```

پیام‌های «بروزرسانی‌های جدید در دسترس هستند» و «تغییرات نسخه‌ی جدید» برای هیچ کاربری نمایش داده نمی‌شوند (در نصب،
هر migrate و راه‌اندازی هر محیط خاموش می‌شوند): بروزرسانی فقط از همین‌جا و به تصمیم شما انجام می‌شود.

**دسترسی از اینترنت:** هر محیط کسب‌وکار با نام کامل دامنه هم ساخته می‌شود (`business.ps1 new shop.example.ir`). اگر
DNS دامنه (و `*.example.ir`) به IP این سرور اشاره کند، `example.ir` و `www.example.ir` و IP سرور سایت اصلی را باز
می‌کنند و `shop.example.ir` محیط همان کسب‌وکار را (`deploy/nginx/sites.conf`). آدرس‌های `*.localhost` فقط روی خود
همین کامپیوتر کار می‌کنند.

### حذف همه‌ی اطلاعات با یک دکمه (حالت آزمایشی)

در «تنظیمات ایرانی» ← «داده‌ی نمونه» ← «حذف همه‌ی اطلاعات (شروع از نو)»: همه‌ی اسناد، مشتری‌ها، تأمین‌کننده‌ها،
کالاها، خودروها، چک‌ها و قراردادها حذف می‌شوند، شماره‌گذاری از ۱ شروع می‌شود و «راه‌اندازی آسان» دوباره باز می‌شود.
شرکت، کدینگ حساب‌ها، سال مالی، کاربران و تنظیمات می‌مانند. برای تأیید باید «حذف همه» تایپ شود.

### داده‌ی نمونه

برای آشنایی با سیستم، در «تنظیمات ایرانی» (`/desk/iran-erp-settings`) از منوی «داده‌ی نمونه» گزینه‌ی «ساخت داده‌ی نمونه»
را بزنید. حدود یک دقیقه طول می‌کشد و برای شرکت پیش‌فرض این‌ها را می‌سازد: ۱۳ کالا و خدمت با قیمت، ۸ مشتری و ۵
تأمین‌کننده با نشانی و تماس، موجودی انبار، فهرست مواد و دستور تولید، سفارش و فاکتور خرید، پیش‌فاکتور، سفارش فروش،
حواله‌ی خروج و فاکتور فروش (پرداخت‌شده، معوقه و پیش‌نویس) با مالیات بر ارزش افزوده، سرنخ و فرصت فروش CRM، پروژه و
وظیفه، تیکت پشتیبانی، کارمند، رویداد تقویم، صفحه‌های وب (درباره ما، محصولات و خدمات، تماس با ما) و چک.
«حذف داده‌ی نمونه» همه‌ی این‌ها را لغو و حذف می‌کند. از خط فرمان:

```bash
docker compose exec backend bench --site frontend execute iran_erp.demo.create_demo_data
docker compose exec backend bench --site frontend execute iran_erp.demo.delete_demo_data
```

### کدینگ حسابداری ایران و مالیات بر ارزش افزوده

- **شرکت جدید:** در ویزارد یا فرم شرکت، کشور «Iran» و نمودار حساب «کدینگ حسابداری ایران» را انتخاب کنید.
- **شرکتی که قبلاً ساخته شده:** به «تنظیمات ایرانی» (`/desk/iran-erp-settings`) بروید و دکمه‌ی «اعمال کدینگ حسابداری ایران»
  را بزنید. این کار همه‌ی حساب‌های فعلی شرکت را حذف می‌کند و فقط برای شرکتی ممکن است که هنوز هیچ سند ثبت‌شده‌ای ندارد.

نرخ مالیات بر ارزش افزوده پیش‌فرض ۱۰٪ است (طبق گزارش‌های منتشرشده از قانون بودجه‌ی ۱۴۰۵). نرخ را با
اعلام رسمی سازمان امور مالیاتی تطبیق دهید و در صورت تغییر، در «تنظیمات ایرانی» یا خود الگوی مالیات عوض کنید.

### چک‌ها

از جستجو «چک» یا آدرس `/desk/iran-cheque` را باز کنید. چک دریافتی پس از ثبت نهایی «در صندوق» است و از منوی
«اقدامات» به بانک واگذار، وصول، برگشت، عودت یا به شخص ثالث واگذار (خرج) می‌شود. هر اقدام یک سند روزنامه‌ی ثبت‌شده
می‌سازد: دریافت چک (بدهکار اسناد دریافتنی ۱۳۰۲، بستانکار مشتری)، واگذاری به بانک (اسناد در جریان وصول ۱۳۰۳)، وصول
(بانک)، و برگشت (بدهکار شدن دوباره‌ی مشتری). چک پرداختی از حساب اسناد پرداختنی ۳۱۰۲ استفاده می‌کند. اگر چک برای
یک فاکتور مشخص باشد، فاکتور تسویه می‌شود؛ وگرنه مبلغ به‌صورت پیش‌دریافت/پیش‌پرداخت می‌ماند تا در «تطبیق پرداخت»
به فاکتور وصل شود. لغو چک همه‌ی اسناد آن را برمی‌گرداند. برای شرکتی که کدینگ ایرانی ندارد، حساب‌ها را در «تنظیمات
ایرانی» تعیین کنید.

### سامانه مؤدیان (آماده‌سازی)

1. در «تنظیمات ایرانی» شناسه یکتای حافظه مالیاتی (۶ کاراکتر، از کارپوشه) را وارد کنید.
2. کد اقتصادی شرکت، کد ملی/شناسه ملی یا کد اقتصادی مشتری‌ها، شناسه‌ی ۱۳ رقمی کالا/خدمت در هر کالا و کد واحد
   مؤدیان در هر واحد اندازه‌گیری را تکمیل کنید.
3. در فاکتور فروشِ ثبت‌شده، از منوی «سامانه مؤدیان» گزینه‌ی «آماده‌سازی برای سامانه مؤدیان» را بزنید. فاکتور یک
   شماره منحصر به فرد مالیاتی می‌گیرد (حافظه + تاریخ + سریال + رقم کنترلی Verhoeff) و داده‌ی صورتحساب با نام فیلدهای
   سازمان (header/body) نمایش داده و قابل دانلود می‌شود. اگر چیزی کم باشد، فهرست آن نشان داده می‌شود و شماره داده نمی‌شود.

**محدودیت مهم:** امضای دیجیتال صورتحساب با کلید خصوصی مؤدی و ارسال به سامانه‌ی مؤدیان هنوز پیاده نشده است و این
داده‌ها با سامانه‌ی واقعی (یا محیط آزمایشی سازمان) آزمایش نشده‌اند. الگوریتم شماره‌ی مالیاتی با نمونه‌ی SDKهای
متن‌باز مؤدیان بررسی شده است. پیش از استفاده‌ی واقعی، آن را با محیط آزمایشی سازمان یا یک شرکت معتمد ارائه‌دهنده
خدمات مالیاتی بسنجید.

نمایش همه‌ی ماژول‌ها (حسابداری، فروش، CRM، وب‌سایت و ...) به‌صورت آیکون در صفحه‌ی اول، به‌جای دو پوشه‌ی
ERPNext و چارچوب:

```bash
docker compose exec backend bench --site frontend execute iran_erp.desktop.use_icon_grid
```

## دستیار بدون هوش مصنوعی (دستورهای آماده)

پنجره‌ی «دستیار هوشمند» حتی بدون هیچ کلید API کار می‌کند: حدود ۹۰ دستور رایج (مانده‌ی حساب، موجودی، فروش و خرید
دوره، فاکتورهای معوق، چک‌های سررسید، سود و زیان، ارزش افزوده، صدور فاکتور و پیش‌فاکتور و سفارش، دریافت و پرداخت،
ثبت چک، تعریف مشتری و کالا، رسید و حواله‌ی انبار، دستور تولید، یادآوری، باز کردن هر فهرست و گزارش با نام فارسی و
...) را موتور دستورهای داخلی روی همین سرور جواب می‌دهد و چیزی به بیرون فرستاده نمی‌شود. فهرست کامل با نمونه‌ها:
[`docs/commands.md`](docs/commands.md).

- جمله‌ها لازم نیست دقیق باشند («احمدی چقدر بدهکاره»، «امروز چقدر فروختیم»، «کالاهایی که داره تموم میشه»)؛
  نام مشتری و کالا از خود سیستم پیدا می‌شود و عدد و مبلغ و تاریخ به هر شکلی («دو و نیم میلیون»، «۵۰۰ هزار تومان»،
  «۳۰ آبان»، «فصل گذشته») خوانده می‌شود.
- اگر جزئیاتی کم باشد می‌پرسد («فاکتور برای کدام مشتری است؟»، «مالیات اضافه شود؟»)، اگر چند مشتری با یک نام باشند
  فهرست می‌دهد، و برای کارهای برگشت‌ناپذیر (ثبت نهایی سند، تغییر قیمت) تأیید می‌گیرد. «لغو» گفتگو را قطع می‌کند.
- **کاربر و دسترسی را خودش می‌سازد:** «برای سرمایه‌گذار رضایی دسترسی درست کن»، «یک کاربر حسابدار بساز به اسم علی
  محمدی نام کاربری ali.m رمز …»، «برای مدیر شعبه کاربر بساز»، «رمز کاربر kazemi رو عوض کن». هر چیزی که نگفته باشید
  (سرمایه‌گذار، نام کاربری، رمز، شعبه) را می‌پرسد. نقش‌ها بر اساس کار شخص داده می‌شوند (پذیرش، فروشنده، حسابدار، مدیر
  مالی، مدیر شعبه، مدیر کل، مشتری) و ورود با نام کاربری فعال می‌شود (`iran_erp/users.py`؛ هوش مصنوعی هم همین را صدا می‌زند).
- **سؤال‌های «چطور …»** را هم خودش جواب می‌دهد، با قدم‌ها و لینک همان صفحه: رمز عبور دادن به کاربر، ساختن کاربر
  و تعیین نقش و دسترسی، کاربر مشتری برای دیدن فاکتورهایش در سایت، فراموشی رمز، غیرفعال کردن کاربر، نام و لوگو،
  نرخ ارزش افزوده، پشتیبان‌گیری، ورود از اکسل، مانده‌ی اول دوره، اصلاح سند ثبت‌شده، گذاشتن خودرو روی سایت و ...
  (`iran_erp/commands/howto.py`؛ برای افزودن سؤال تازه یک بخش به همین فهرست اضافه کنید). «چطور مشتری/کالا/فاکتور جدید
  بسازم» هم قدم‌های همان فرم را می‌دهد و پیشنهاد می‌کند همان‌جا بسازد. این جواب‌ها حتی وقتی هوش مصنوعی فعال است
  اول از سیستم می‌آیند.
- چیزی که تشخیص ندهد، درخواست‌های چندبخشی، تحلیل‌ها («چرا فروش کم شده») و فایل‌های پیوست، اگر هوش مصنوعی فعال
  باشد به آن فرستاده می‌شود؛ وگرنه نزدیک‌ترین دستورها را پیشنهاد می‌دهد.
- در «دستور چت» (`/desk/iran-chat-command`) می‌شود بدون برنامه‌نویسی دستور تازه (پاسخ، باز کردن فهرست با فیلتر،
  گزارش، ...) یا جمله‌های تازه برای دستورهای آماده تعریف کرد. ستون «پاسخ‌دهنده» در «درخواست‌های دستیار» نشان می‌دهد
  کدام پیام‌ها تشخیص داده نشده‌اند.
- خاموش و روشن کردنش با گزینه‌ی «پاسخ به دستورهای شناخته‌شده بدون هوش مصنوعی» در «تنظیمات دستیار هوشمند» است.
- زیر هر جواب نوشته شده چه کسی جواب داده: **دستورهای سیستم** (سبز) یا **هوش مصنوعی** (بنفش). اگر جواب سیستم درست
  نبود، دکمه‌ی «درست نبود؟ از هوش مصنوعی بپرس» همان سؤال را به هوش مصنوعی می‌دهد.
- **یادگیری:** وقتی هوش مصنوعی درخواستی را انجام می‌دهد که یکی از دستورها هم انجامش می‌دهد (مثلاً ثبت دریافت، فاکتور،
  چک)، یا وقتی کاربر از فهرست «منظورتان کدام است؟» یکی را انتخاب می‌کند، آن جمله (بدون نام‌ها و عددها) به دستور
  اضافه می‌شود و دفعه‌ی بعد بدون هوش مصنوعی جواب داده می‌شود. جمله‌های یادگرفته در «دستور چت» با تیک «یادگرفته‌شده»
  دیده و ویرایش می‌شوند؛ دکمه‌ی «درست نبود» جمله‌ی یادگرفته‌ی اشتباه را پاک می‌کند.
- **روش‌های آموخته‌شده:** هر کار دیگری هم که هوش مصنوعی با ابزارهایش انجام دهد (جست‌وجو و فهرست با شرط‌های خاص،
  اجرای گزارش، ساخت سند پیش‌نویس، تعریف مشتری یا کالا) به‌صورت یک «روش آموخته‌شده» ذخیره می‌شود: مشتری، کالا، حساب
  بانکی، مبلغ، تاریخ و بازه‌ی پیام جای خالی می‌شوند و بقیه همان می‌ماند. دفعه‌ی بعد که کسی همین را با نام‌ها و عددهای
  دیگر بخواهد، سیستم خودش و بدون هوش مصنوعی انجامش می‌دهد (اگر چیزی کم باشد می‌پرسد، «این ماه» را دوباره حساب
  می‌کند و مبلغ تومان را ریال می‌کند). کارهایی که سند می‌سازند پیش از اجرا تأیید می‌گیرند. با هر درخواست تازه روش‌های
  بیشتری یاد گرفته می‌شود و نیاز به هوش مصنوعی کم‌تر می‌شود. روش‌ها در «روش آموخته‌شده» دیده، ویرایش یا غیرفعال
  می‌شوند؛ «درست نبود» و دو بار خطا هم روش را خاموش می‌کند. درخواست‌هایی که فایل پیوست دارند یاد گرفته نمی‌شوند.
- حساب‌های بانکی را با نامی که می‌شناسید صدا بزنید («حساب ملت»، «بانک ملت شرکا»): دریافت و پرداخت به همان حساب ثبت
  می‌شود و هوش مصنوعی هم فهرست حساب‌های بانکی، صندوق‌ها، انبارها و روش‌های پرداخت شرکت را از قبل می‌داند.

## ظاهر فارسی

- **تاریخ شمسی:** با کلیک روی هر فیلد تاریخ، تقویم شمسی باز می‌شود؛ کلیک روی عنوان ماه، فهرست ماه‌ها و بعد فهرست
  سال‌ها را می‌آورد تا روز، ماه و سال مستقیم انتخاب شود.
- **فهرست‌های کشویی:** کلیک روی فیلدی که مقدار دارد (مشتری، مدل خودرو و …) همه‌ی گزینه‌ها را نشان می‌دهد؛ لازم نیست
  اول مقدار را پاک کنید.

- **عددها همه با رقم فارسی** نشان داده می‌شوند (۰ تا ۹): یک قلم کوچک از وزیرمتن رقم‌های ۰ تا ۹ را فارسی می‌کشد،
  پس آنچه ذخیره، تایپ، کپی و حساب می‌شود تغییری نمی‌کند.
- حرف‌های فارسی با قلم وزیرمتن و بدون فاصله‌ی بین حروف نوشته می‌شوند.
- **ستون جدول گزارش‌ها به اندازه‌ی محتوایش** است (بلندترین عنوان یا مقدار در ردیف‌ها، با تورفتگی درختی)؛ اگر جدول از
  صفحه باریک‌تر باشد پهن می‌شود تا صفحه را پر کند و فقط وقتی واقعاً جا نشود اسکرول افقی دارد.
- نمودارها ماه شمسی و مقدارهای خوانا («۳ میلیارد ریال») دارند؛ سال مالی‌ای که دقیقاً از ۱ فروردین تا آخر اسفند است
  ولی نام میلادی دارد («2026-2027») با `migrate` به نام شمسی («1405») تغییر می‌کند.
- نام و شرح دسته‌بندی‌های حساب، قالب‌های چاپ، الگوهای گزارش مالی و انبارها/بخش‌ها/مراکز هزینه‌ی پیش‌فرض هر شرکت
  فارسی است.

- **ریال بعد از عدد** نوشته می‌شود، همان‌طور که در حسابداری ایرانی رایج است («۳۵٬۰۰۰ ریال»)، و منفی‌ها درست
  نمایش داده می‌شوند («-۳۵٬۰۰۰ ریال»)؛ عنوان ستون‌ها و فیلدها هم «(ریال)» دارد نه «(IRR)». مانده‌های نمودار حساب
  «بدهکار»/«بستانکار» نوشته می‌شوند.
- **متن فارسی همه‌جا راست‌چین** است: ستون‌های جدول گزارش‌ها از راست شروع می‌شوند و نوع سندها («ثبت پرداخت»،
  «فاکتور فروش») به فارسی نشان داده می‌شوند.
- **ستون‌های فهرست‌ها** (مثل فهرست ثبت پرداخت) هم به اندازه‌ی محتوایشان اندازه می‌گیرند؛ اگر کمی جا کم باشد فقط
  بلندترین ستون‌ها کوتاه می‌شوند تا ستون‌های کوتاه مثل شناسه کامل دیده شوند. اندازه‌ای که کاربر با کشیدن لبه‌ی
  ستون بدهد حفظ می‌شود.
- «Submit» در همه‌جا «ثبت نهایی» و «Submitted» «ثبت‌شده» است (نه «ارسال»).
- صفحه‌ی ورود هم فارسی است (حتی اگر زبان مرورگر انگلیسی باشد)، «درباره» نام ERP-VERON، برنامه‌نویس و وب‌سایت
  [erpveron.com](https://erpveron.com) را نشان می‌دهد، و پیوندهای پشتیبانی و مستندات سازنده‌ی فریم‌ورک و تبلیغ‌های منوی
  کناری برداشته شده‌اند.

## آموزش داخلی هر صفحه

دکمه‌ی «آموزش» بالای هر صفحه راهنمای کامل همان صفحه را باز می‌کند؛ این راهنماها همراه برنامه نوشته شده‌اند و به
هوش مصنوعی نیازی ندارند (`iran_erp/help/content/`؛ بیش از ۱۰۰ فرم و فهرست، ۳۷ گزارش و ۱۶ بخش اصلی):

- این صفحه برای چیست، پیش از شروع چه چیزهایی لازم است، کار قدم‌به‌قدم، پس از «ثبت نهایی» چه اتفاقی در حساب‌ها و
  انبار می‌افتد، اشتباه‌های رایج و راه درست کردنشان، نکته‌ها، یک مثال واقعی با ریال و تاریخ شمسی و صفحه‌های مرتبط.
- **کادر دور هر بخش:** با کلیک روی هر فیلد، بخش، زبانه، فیلتر یا ستون در راهنما، دور همان قسمت صفحه کادر کشیده
  می‌شود (اگر در زبانه‌ی دیگری باشد آن زبانه باز می‌شود و پنل راهنما کنار می‌رود تا روی آن را نگیرد).
- **تور قدم‌به‌قدم:** دکمه‌ی «تور قدم‌به‌قدم این صفحه» بخش‌های صفحه را یکی‌یکی با کادر و توضیح نشان می‌دهد
  (با «بعدی»/«قبلی» یا کلیدهای جهت؛ Esc پایان می‌دهد).
- **جستجو در راهنما** و پیوند «صفحه‌های مرتبط» برای خواندن راهنمای صفحه‌های دیگر بدون رفتن به آن‌ها.
- مدیر سیستم می‌تواند در «راهنمای صفحه» متن بیشتری برای هر صفحه بنویسد؛ زیر همان راهنما نشان داده می‌شود.

## بسته‌ی شغلی و نمایشگاه خودرو

در «راه‌اندازی آسان»، قدم اول («کسب‌وکار شما») می‌پرسد کار شما چیست و چند شعبه دارید. هر نوع کار یک «بسته‌ی شغلی»
است (`iran_erp/business/`) که صفحه‌ها و حساب‌های لازم آن کار را اضافه و بخش‌های بی‌استفاده را پنهان می‌کند.

- **شعبه‌ها (برای هر کسب‌وکاری):** هر شعبه یک «شعبه» است و شعبه بُعد حسابداری است؛ هر سند و ردیف دفتر شعبه‌ی خودش را
  دارد و گزارش‌ها برای هر شعبه جدا گرفته می‌شوند.
- **انتخاب‌های مخصوص هر کار:** با انتخاب نوع کار، امکانات همان کار با تیک نشان داده می‌شوند (برای نمایشگاه: فروش
  اقساطی، سرمایه‌گذاران، خرید حواله، فروش امانی، آماده‌سازی و هزینه‌ها، پارکینگ‌ها) و هر چه تیک نخورد از منو پنهان
  می‌شود. نام پارکینگ‌ها هم همان‌جا پرسیده می‌شود.
- **نمایشگاه خودرو** (ماژول جدا با منوی خودش، `iran_erp/iran_dealership/`):
  - **داشبورد:** با نام نمایشگاه و تاریخ امروز؛ خودروهای نمایشگاه، فروش و سود خالص این ماه با مقایسه با ماه قبل،
    نقدینگی ۷ روز آینده (چک‌های دریافتنی منهای پرداختنی)، اقساط معوق و پرداختنی به سرمایه‌گذاران؛ نوار وضعیت
    نمایشگاه و روزهای ماندن خودروها؛ **نمودار ماه‌به‌ماه** که هر مورد آن تیک می‌خورد (فروش خودرو، سود فروش خودرو،
    سود اقساط، هزینه خدمات، سود سرمایه‌گذاران، سود خالص، خرید خودرو، وصول اقساط) به‌صورت ستونی، خطی یا جدول، برای
    ۶، ۱۲ یا ۲۴ ماه؛ پر شدن پارکینگ‌ها، طولانی‌ترین ماندن‌ها و آخرین رویدادها. مدیر می‌تواند شعبه را عوض کند.
  - **نام کسب‌وکار:** در قدم اول «راه‌اندازی آسان» (یا «تنظیمات ایرانی»): نام، تلفن، آدرس و لوگو؛ روی داشبورد، چاپ
    «پرونده خودرو» و صفحه‌ی سرمایه‌گذاران نوشته می‌شود.
  - **سال ساخت:** هر مدل «ساخت داخل» یا «وارداتی» است؛ سال ساخت خودروی داخلی شمسی (۱۴۰۳) و وارداتی میلادی (۲۰۲۴)
    ثبت می‌شود.
  - **پرونده‌ی خودرو:** هر خودرو یک کد می‌گیرد (`CAR-00001`). زبانه‌ها: خودرو (مدل و رنگ از فهرست، سال، پلاک، کارکرد،
    شاسی، شعبه، پارکینگ و شماره جایگاه) / مالک و قیمت (خود مجموعه، سرمایه‌گذار یا مشتری امانی با حق‌العمل؛ قیمت فروش و
    کف قیمت؛ تیک مدارک تحویل‌گرفته: سند، کارت، بیمه، سوئیچ یدک، خلافی، ...) / وضعیت بدنه (کلیک روی قسمت‌های نقشه‌ی
    خودرو و تیک رنگ دارد، تصادفی، خط و خش، لیسه، تعویضی، رنگ‌سوختگی با توضیح) / وضعیت فنی و داخلی (نمره‌ی ۱ تا ۱۰ یا
    درصد لاستیک با دیدگاه) / خدمات و هزینه‌ها (از فهرست خدمات، کلی یا موضعی، تعمیرگاه خودمان یا بیرون، برنامه‌ریزی‌شده
    یا انجام‌شده؛ جمع آماده‌سازی، تعمیرات و امور اداری جدا) / فروش و خروج / پرونده خودرو (هر اتفاق با تاریخ و کاربر).
    چاپ «پرونده خودرو» همه را یک‌جا با نقشه‌ی رنگی بدنه چاپ می‌کند.
  - **پذیرش خودرو (دسترسی جدا):** در داشبورد نمایشگاه «کارمند پذیرش جدید» برای او کاربر می‌سازد. پذیرش بعد از ورود
    مستقیم فهرست خودروها را می‌بیند و در یک فرم خودرو را ثبت می‌کند: مدل (مشخصات فنی خودکار می‌آید)، سال، رنگ، پلاک،
    کارکرد، پارکینگ، قیمت فروش، مدارک، وضعیت بدنه روی نقشه، کارشناسی فنی و داخلی، عکس‌ها، و با تیک «نمایش در سایت»
    همان لحظه روی سایت. قیمت خرید، کف قیمت، مالک و سرمایه‌گذار، هزینه‌ها، فروش و حساب‌ها را نمی‌بیند (سطح دسترسی ۱).
  - **مشخصات فنی هر مدل:** در «مدل‌های خودرو» یک بار نوشته می‌شود (موتور، حجم، قدرت، گشتاور، گیربکس، سوخت، مصرف،
    باک، دیفرانسیل، سرنشین، سرعت، شتاب، کیسه هوا، طول، صندوق، امکانات دیگر) و برای هر خودروی آن مدل در پرونده، چاپ و
    سایت نشان داده می‌شود. برای مدل‌های رایج مقادیر معمول از پیش پر شده‌اند (بدون مصرف سوخت)؛ آن‌ها را بررسی و کامل کنید.
  - **شعبه‌ی خودکار:** در فرم هر کاربر «شعبه»ی او را انتخاب کنید؛ خودروهایی که ثبت می‌کند در همان شعبه می‌نشینند و
    فقط مدیر سیستم می‌تواند شعبه‌ی خودرو را عوض کند (در پرونده ثبت می‌شود).
  - **تنظیمات نمایشگاه:** فهرست‌های قابل ویرایش مدل‌ها (حدود ۸۰ مدل بازار ایران)، رنگ‌ها، قطعه‌های بدنه، وضعیت‌های
    بدنه، موارد بازدید فنی، خدمات و پارکینگ‌ها.
  - هزینه‌ها در دفاتر: روی ارزش خودروی مجموعه، به حساب مالک اگر هزینه‌ها با اوست، وگرنه «هزینه آماده‌سازی خودرو»؛
    کار بیرون بدون پرداخت، بدهی به تعمیرگاه می‌شود.
  - **فروش اقساطی:** پیش‌پرداخت و اقساط با سود ثابت ماهانه روی مبلغ اقساطی (۱ میلیارد × ۶٪ × ۱۰ ماه = ۶۰۰ میلیون
    سود)، جدول اقساط، ساخت یک‌جای چک همه‌ی اقساط، پرداخت نقدی قسط، جریمه‌ی دیرکرد روزشمار، تسویه‌ی زودتر با کم شدن
    سود روزهای باقی‌مانده. سود در سررسید هر قسط از «سود تحقق‌نیافته» به درآمد می‌رود (کار روزانه).
  - **سرمایه‌گذاران:** قرارداد با مبلغ، تعداد ماه و درصد سود ماهانه (پرداخت ماهانه یا در سررسید)، سود روزشمار تا
    امروز، صدور یک‌جای چک‌های سود و اصل هنگام سپردن پول، و «سرمایه‌گذاری مجدد» (پرداخت‌های انجام‌نشده با برگشت
    چک‌ها یا پول چک‌های پاس‌شده) که قرارداد تازه را به قرارداد قبلی زنجیر می‌کند؛ حد نصاب در «تنظیمات ایرانی».
    سرمایه می‌تواند برای کل مجموعه، یک شعبه یا یک خودرو باشد. **خرید حواله‌ی خودرو:** خودرو مال سرمایه‌گذار است و
    با فروشش، قیمت منهای حق‌العمل مجموعه به حساب او می‌رود.
  - **«حساب من» برای سرمایه‌گذار:** روی سرمایه‌گذار «ساخت کاربر ورود» را بزنید؛ سرمایه‌گذار با ورود فقط صفحه‌ی خودش را
    می‌بیند (سرمایه‌ی فعال، سود تا امروز، چک‌ها و پرداخت‌های آینده) و به هیچ سند دیگری دسترسی ندارد، مگر نقش بیشتری
    به او بدهید.
  - گزارش‌ها: «موجودی خودروها» (با روزهای ماندن؛ بیش از ۶۰ روز قرمز)، «هزینه‌های خودروها» (به تفکیک خدمت یا خودرو)،
    «پیش‌بینی نقدینگی اقساط و سرمایه‌گذاران» (ماه‌به‌ماه، ماه‌های کم‌پول قرمز) و «اقساط معوق».
  - **داده‌ی نمونه‌ی نمایشگاه:** ۲۰ خودرو با مدل‌ها و مالک‌های مختلف (مجموعه، مشتری امانی، سرمایه‌گذار حواله)، ۵
    سرمایه‌گذار با قراردادهای مختلف (سود ماهانه، سود در سررسید، شعبه‌ای، سرمایه‌گذاری مجدد، حواله) و ۵ فروش اقساطی با
    چک‌ها:

    ```
    docker compose exec backend bench --site frontend execute iran_erp.iran_dealership.demo.create_dealership_demo
    docker compose exec backend bench --site frontend execute iran_erp.iran_dealership.demo.delete_dealership_demo
    ```
- **سایت نمایشگاه (`/cars`):** صفحه‌ی عمومی برای مشتری‌ها، با نام و رنگ نمایشگاه:
  - **فهرست خودروها:** جستجو و فیلتر برند، نوع بدنه، داخلی یا وارداتی، بازه‌ی قیمت (تومان یا ریال) و ترتیب قیمت؛
    خودروهای ویژه اول؛ کارت هر خودرو با عکس (یا تصویر خودرو در رنگ خودش)، سال، کارکرد، رنگ و قیمت.
  - **صفحه‌ی هر خودرو (`/cars/CAR-00001`):** عکس‌ها؛ **نمای سه‌بعدی ۳۶۰ درجه** روی سکوی چرخان که با ماوس یا انگشت
    زاویه‌ی دوربین عوض می‌شود و با اسکرول زوم می‌شود، با دکمه‌های باز کردن درها و کاپوت و نمای جلو/کنار/عقب/بالا
    (اگر برای مدل فایل GLB گذاشته شود همان مدل واقعی نشان داده می‌شود و انیمیشن‌هایش دکمه می‌گیرند)؛ مشخصات، امکانات،
    مدارک، نقشه‌ی وضعیت بدنه و گزارش کارشناسی؛ **شبیه‌سازی خرید اقساطی** (پیش‌پرداخت با اسلایدر و تعداد ماه‌ها، با
    همان حساب قرارداد)؛ کارشناسان با تماس و واتس‌اپ؛ خودروهای مشابه.
  - **درخواست مشتری:** «رزرو تست‌درایو»، «با من تماس بگیرید» و «این طرح را می‌خواهم» یک «درخواست مشتری» می‌سازد که
    به نوبت به کارشناس سپرده می‌شود (در «کارهای من» او)؛ روی داشبورد تعداد درخواست‌های جدید دیده می‌شود و از خود
    درخواست با «ساخت فروش اقساطی» مشتری و طرح انتخابی‌اش به فروش اقساطی می‌رود.
  - تنظیمات در «نمایشگاه خودرو ← وب‌سایت ← تنظیمات سایت نمایشگاه»؛ برای هر خودرو زبانه‌ی «وب‌سایت» (نمایش در سایت،
    عکس‌ها، تیتر، امکانات). قیمت خرید، کف قیمت، مالک و حساب‌ها هیچ‌وقت روی سایت نشان داده نمی‌شوند.
  - «وب‌سایت ← باز کردن سایت» و دکمه‌ی «دیدن در سایت» به سایت اتومدیران می‌روند (نشانی در «تنظیمات سایت نمایشگاه
    ← نشانی سایت نمایشگاه»؛ خالی: همین سرور روی پورت ۸۰). صفحه‌های داخلی خود سیستم هنوز در `/cars` هستند.
  - **سایت اتومدیران کنار سیستم:** با `COMPOSE_PROFILES=website` در `.env` (یا `docker compose --profile website up -d`)
    سایت از GitHub ساخته و روی پورت ۸۰ اجرا می‌شود و خودروها را از همین سیستم می‌خواند (`WEBSITE_REF` شاخه‌ی آن،
    `WEBSITE_ERP_HOST` محیطی که نشان می‌دهد).
  - **سایت جداگانه‌ی نمایشگاه** (مثلاً سایت React اتومدیران) همین خودروها را به‌صورت JSON می‌خواند:
    `GET /api/method/iran_erp.iran_dealership.showroom.get_inventory` (خودروها با عکس، قیمت به تومان، سال با
    شمسی/میلادی، مشخصات فنی مدل، امکانات، مدارک و برگه‌ی کارشناسی رنگ و بدنه) و درخواست‌های مشتری را با
    `POST .../showroom.send_inquiry` می‌فرستد؛ همان قاعده‌ها: فقط خودروهای «نمایش در سایت» و فقط چیزهایی که خریدار
    باید ببیند. سرور آن سایت بهتر است `/api` و `/files` را به ERP بدهد (در مخزن automodiran: `deploy/`)؛ اگر سایت از
    آدرس دیگری مستقیم وصل می‌شود: `bench --site frontend set-config allow_cors '"https://automodiran.ir"'`.
- **پلاک ایرانی:** پلاک در چهار خانه وارد می‌شود (دو رقم، حرف، سه رقم، کد شهر) و مثل خود پلاک (نوار آبی، شماره،
  «ایران ۶۷») روی فرم، داشبورد، پرونده‌ی چاپی و پنل سرمایه‌گذار دیده می‌شود؛ پلاک نادرست ذخیره نمی‌شود.
- **پرداخت ماهانه به سرمایه‌گذار:** حالت پیش‌فرض قرارداد «ماهانه، سود و بخشی از اصل» است: هر ماه یک چک برابر
  (سرمایه + کل سود) ÷ تعداد ماه؛ یعنی سرمایه ماه‌به‌ماه برمی‌گردد. فقط سهم سود هر پرداخت هزینه‌ی مجموعه ثبت می‌شود.
  حالت‌های «فقط سود ماهانه و اصل در پایان» و «همه در پایان» هم هست.
- **داشبورد به تناسب بیننده:** مدیر کل (مدیر سیستم، یا مدیری که شعبه‌ی خودش را ندارد) همه‌ی شعبه‌ها را کنار هم می‌بیند:
  تعداد خودرو، ارزش دارایی مجموعه (به بهای تمام‌شده)، خودروهای امانی (به قیمت پیشنهادی)، خودروهای سرمایه‌گذاران، فروش
  و سود این ماه هر شعبه. مدیر شعبه شعبه‌ی خودش را می‌بیند و فهرست خودروهای شعبه‌های دیگر را که می‌تواند بفروشد. هر عدد
  با کلیک فهرست همان خودروها را با پلاک، مالک، هزینه و قیمت باز می‌کند. شعبه‌ی هر کاربر در فیلد «شعبه»ی کاربر است.
- **سرمایه‌گذار با نام کاربری و رمز:** در فرم سرمایه‌گذار «ساخت کاربر ورود» (یا «تغییر نام کاربری یا رمز»)؛ یا به دستیار
  بگویید «برای سرمایه‌گذار رضایی دسترسی درست کن». سرمایه‌گذار بعد از ورود مستقیم به «حساب من» می‌رود: سرمایه‌ی فعال،
  سود تا امروز و سود سالانه، باقی‌مانده‌ی طلبش، پرداخت بعدی و شماره‌ی چکش، نمودار ماه‌به‌ماه سود و پرداخت‌ها،
  قراردادها با جدول پرداخت، همه‌ی چک‌ها (پاس‌شده، در دست)، خودروهایی که با سرمایه‌اش خرید و فروش شده و گردش حسابش.
- **چاپ چک:** روی چک صادرشده «چاپ ← چاپ روی برگ چک»: تاریخ، تاریخ به حروف، مبلغ به عدد و حروف، در وجه، کد ملی و بابت
  در جای خودشان. «چاپ آزمایشی (با خط‌کش)» برای تنظیم جای هر مورد در «قالب چاپ چک» (برای هر بانک یک قالب).

## راه‌اندازی آسان

صفحه‌ی **راه‌اندازی آسان** (آیکون آن در صفحه‌ی اصلی، و نوار «شروع راه‌اندازی» بالای صفحه‌ی «شروع کار» تا وقتی تمام نشده)
سیستم را با سؤال‌هایی درباره‌ی کسب‌وکار راه می‌اندازد، نه سؤال‌های حسابداری. هر قدم می‌گوید برای چیست، یک مثال واقعی
دارد و دکمه‌ی «بیشتر بدانید» راهنمای همان بخش را باز می‌کند:

1. **کسب‌وکار شما:** نوع کار، کالا یا خدمت، انبار، ارزش افزوده، چک و تاریخ شروع. بخش‌هایی که لازم نیست (انبار، تولید،
   چک) از صفحه‌ی اصلی پنهان می‌شوند و بدون ارزش افزوده، فاکتورها الگوی مالیات ندارند.
2. **بانک‌ها و صندوق:** برای هر حساب بانکی، بانک، حساب دفتر کل و «حساب بانکی» خودکار ساخته می‌شود.
3. **انبارها**، 4. **مشتری‌ها و طلب‌ها**، 5. **تأمین‌کننده‌ها و بدهی‌ها**، 6. **کالاها و موجودی انبار**، 7. **چک‌های در جریان**:
   هر جدول را می‌شود دستی پر کرد یا از اکسل کپی کرد و با «چسباندن از اکسل» آورد؛ ستون‌ها از روی عنوان یا محتوا
   (موبایل، کد ملی، عددها) شناخته می‌شوند. ردیف‌های مشکل‌دار با شماره و توضیح فارسی گزارش می‌شوند.
8. **بازبینی و ثبت:** جمع دارایی‌ها و بدهی‌ها و سرمایه نشان داده می‌شود، با فهرست مشکل‌ها (حساب جاافتاده، کالای بی‌قیمت،
   سرمایه‌ی منفی، ...). «ثبت مانده‌های اول دوره» همه را یک‌جا ثبت می‌کند و اگر جایی خطا بدهد هیچ چیز ثبت نمی‌شود: سند
   افتتاحیه‌ی صندوق و بانک، فاکتورهای افتتاحیه برای طلب و بدهی (تا پرداخت‌های بعدی به آن‌ها وصل شوند)، تطبیق انبار
   افتتاحیه، چک‌ها در «چک» و انتقال مانده‌ی «افتتاحیه موقت» به «سرمایه». سال مالی شمسی اگر نباشد ساخته می‌شود.

## صفحه‌ی «شروع کار» برای تازه‌کارها

بعد از ورود، کاربر به صفحه‌ی **شروع کار** می‌رود (در «تنظیمات ایرانی» با گزینه‌ی «باز شدن صفحه‌ی شروع کار بعد از ورود»
خاموش می‌شود؛ آیکون «شروع کار» در صفحه‌ی اصلی هم هست):

- بالای صفحه ارقام امروز: فروش این ماه، طلب از مشتری‌ها، بدهی به تأمین‌کننده‌ها، موجودی صندوق و بانک، چک‌های سررسید تا
  یک هفته و کارهای منتظر کاربر؛ هر کدام با یک کلیک به گزارشش می‌رود.
- دکمه‌های بزرگ کارهای روزانه به زبان ساده (فاکتور فروش، دریافت پول از مشتری، فاکتور خرید، پرداخت، چک دریافتی و پرداختی،
  ورود و خروج کالا، مشتری و کالای جدید، یادآوری، ...). هر دکمه یک **فرم ساده** باز می‌کند که فقط چیزهای لازم را با
  توضیح می‌پرسد و همان دستوری را اجرا می‌کند که چت اجرا می‌کند؛ نتیجه پیش‌نویس است و با یک دکمه باز می‌شود.
- گزارش‌های ساده (سود و زیان، بدهکاران، پرفروش‌ها) جوابشان را در چت می‌دهند.

در چت هم زیر هر سؤال سیستم **دکمه‌ی جواب** هست: «بله / نه» برای تأیید، گزینه‌های شماره‌دار، «با / بدون ارزش افزوده»،
«نقدی / واریز به حساب»، «این ماه / ماه قبل / امسال» و **انتخاب از فهرست** برای مشتری، کالا، حساب بانکی و ...؛ پیام
خوشامد هم چند کار پرکاربرد را به‌صورت دکمه پیشنهاد می‌دهد. پس کاربر بدون تایپ هم می‌تواند کار کند.

## دستیار هوشمند (OpenRouter، AgentRouter، Groq یا هر سرویس سازگار)

در «تنظیمات دستیار هوشمند» با فیلد **ارائه‌دهنده** سرویس را انتخاب کنید. کلید و مدل هر ارائه‌دهنده جدا نگه داشته
می‌شود:

| ارائه‌دهنده | آدرس | توضیح |
|---|---|---|
| OpenRouter | خودکار | پیش‌فرض؛ با «مدل‌های جایگزین» |
| AgentRouter | خودکار | نام مدل همان‌طور که در agentrouter.org نوشته شده؛ برای مدل‌های `chat` فرمت «OpenAI Chat» و برای مدل‌های فقط `claude_native` (مثل Claude) فرمت «Anthropic Messages» |
| Groq | خودکار | کلید از console.groq.com/keys (می‌شود چند کلید را با کاما جدا کرد)؛ مدل پیش‌فرض `openai/gpt-oss-120b`. ورود صوتی با «مدل هوش مصنوعی» از Whisper (`whisper-large-v3`) استفاده می‌کند که فارسی را خوب می‌فهمد. در طرح رایگان سقف توکن در دقیقه کم است و درخواست‌های پشت‌سرهم کمی صبر می‌کنند |
| سفارشی | دستی | هر سرویسی که API سازگار با OpenAI یا Anthropic دارد |

> **توجه:** AgentRouter فقط درخواست ابزارهای برنامه‌نویسی پشتیبانی‌شده‌ی خودش (مثل Claude Code و Codex) را می‌پذیرد و به
> نرم‌افزارهای دیگر خطای `401 unauthorized client detected` می‌دهد؛ پس با کلید فعلی‌اش در این سیستم کار نمی‌کند.

**چند کلید:** در فیلد کلید هر ارائه‌دهنده می‌شود تا ۳۰ کلید را با کاما جدا وارد کرد. کلیدی که رد شود (401/403)، اعتبارش
تمام شود (402) یا به سقف درخواست برسد (429) مدتی کنار گذاشته می‌شود و درخواست بی‌درنگ با کلید بعدی فرستاده می‌شود.
سقف درخواست در Groq و بیشتر سرویس‌ها برای کل حساب (سازمان) است، پس چند کلید از یک حساب سقف را بالا نمی‌برد؛ چند
کلید برای پشتیبان بودن و جدا کردن کلید هر بخش مفید است.

### راه‌اندازی OpenRouter

1. یک کلید API از [openrouter.ai/keys](https://openrouter.ai/keys) بسازید و اعتبار حساب را شارژ کنید.
2. در ERPNext به آدرس `/desk/iran-ai-settings` بروید (یا در جستجو «تنظیمات دستیار هوشمند» را بنویسید).
3. کلید را وارد کنید، شناسه‌ی مدل را از [openrouter.ai/models](https://openrouter.ai/models) بگذارید
   (پیش‌فرض `anthropic/claude-opus-5.5`) و ذخیره کنید. دکمه‌ی «آزمایش اتصال» کلید و مدل را بررسی می‌کند.
4. صفحه را بازخوانی کنید؛ دکمه‌ی «دستیار هوشمند» پایین صفحه ظاهر می‌شود.

با دکمه‌ی میکروفون (🎤) می‌توانید به‌جای تایپ، فارسی صحبت کنید؛ متن در کادر نوشته می‌شود و بعد آن را می‌فرستید.
در «تنظیمات دستیار هوشمند»، بخش «ورود صوتی» دو حالت هست:

- **مرورگر** (پیش‌فرض): تشخیص گفتار رایگان Chrome و Edge؛ در فارسی ضعیف‌تر است.
- **مدل هوش مصنوعی**: صدا ضبط و به یک مدل صوتی در OpenRouter فرستاده می‌شود (در «مدل تبدیل گفتار به متن» مدلی را
  بگذارید که ورودی audio می‌پذیرد). نام کالاها و مشتری‌های سیستم هم به مدل داده می‌شود تا درست نوشته شوند. دقیق‌تر
  است و مثل هر درخواست دیگری هزینه دارد.

میکروفون در هر دو حالت فقط روی `localhost` یا آدرس HTTPS کار می‌کند، نه روی `http://IP-سرور`.

با دکمه‌ی گیره (📎) در پنل دستیار می‌توانید فایل پیوست کنید:

- **صورت‌حساب بانک (XLSX یا CSV):** مثلاً بنویسید «این صورت‌حساب را با حساب بانک ملت تطبیق بده». دستیار ستون‌ها را
  تشخیص می‌دهد (تاریخ شمسی، واریز، برداشت، شماره پیگیری، مانده)، هر ردیف را با اسناد همان حساب بانکی در دفاتر
  (همان مبلغ و حداکثر ۳ روز اختلاف تاریخ؛ شماره چک/پیگیری اولویت دارد) جفت می‌کند و ردیف‌های بی‌جفت دو طرف و
  اختلاف مانده‌ها را گزارش می‌دهد. برای کارمزدها و سودهای ثبت‌نشده، با تأیید شما سند روزنامه‌ی پیش‌نویس می‌سازد.
- **فاکتور خرید (عکس یا PDF):** دستیار ردیف‌ها، تأمین‌کننده (با نام، کد اقتصادی یا شناسه ملی)، شماره و تاریخ
  فاکتور را می‌خواند و یک فاکتور خرید پیش‌نویس با مالیات بر ارزش افزوده می‌سازد و فایل را به آن پیوست می‌کند. اگر
  جمع فاکتور با جمع محاسبه‌شده فرق داشته باشد، هشدار می‌دهد. برای خواندن عکس، مدلی را انتخاب کنید که تصویر
  می‌پذیرد (مدل‌های Claude، GPT و Gemini همگی می‌پذیرند).

دستیار با دسترسی‌های همان کاربری کار می‌کند که سؤال می‌پرسد، فقط سند **پیش‌نویس** می‌سازد و هیچ سندی را
ثبت نهایی، لغو یا حذف نمی‌کند. ساخت یا تغییر رکوردهای تنظیمات سیستم (کاربران، نقش‌ها، سفارشی‌سازی‌ها) برایش
بسته است. همه‌ی سؤال‌ها و کارهای انجام‌شده در «درخواست دستیار هوشمند» (`/desk/iran-ai-request`) ثبت می‌شوند.

## به‌روزرسانی سرور بعد از تغییرات جدید

روی ویندوز: `deploy\update.ps1` (بخش «پنل مشتری‌ها و بروزرسانی یک‌جا»). یا دستی:

```bash
cd ~/majidehtesham4 && git pull
cd erpnext-iran && docker build -t iran-erp:latest .
cd deploy && docker compose up -d
docker compose exec backend bench --site all migrate
```

برای اتصال دامنه و HTTPS از راهنمای
[frappe_docker](https://github.com/frappe/frappe_docker/tree/main/docs) استفاده کنید.

## توسعه

کد اپ در `apps/iran_erp` است. برای اجرای تست‌ها داخل یک bench:

```bash
bench --site <site> set-config allow_tests true
bench --site <site> run-tests --app iran_erp
```
