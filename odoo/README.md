# نصب آزمایشی Odoo 19 (Community)

برای بررسی Odoo کنار ERP-VERON. سیستم فعلی دست نمی‌خورد: ERP-VERON روی پورت 8080 می‌ماند و Odoo روی 8069 اجرا
می‌شود، با پایگاه داده‌ی جدای خودش.

## فضای لازم
- ایمیج Odoo 19: حدود ۳٫۳ گیگ
- ایمیج PostgreSQL 16: حدود ۰٫۶ گیگ
- پایگاه داده‌ی خالی به زبان فارسی: حدود ۱۰۰ مگ (با ماژول‌ها و داده‌ی نمونه تا ۱ گیگ)
- **جمع:** حدود ۴ تا ۵ گیگ. پیشنهاد: دست‌کم ۱۰ گیگ فضای خالی.

## نصب (یک بار)
۱. Docker Desktop را باز کنید و صبر کنید سبز شود.

۲. نسخه‌ی تازه‌ی مخزن را بگیرید و اجرا کنید:
```powershell
cd D:\majidehtesham4
git pull
cd odoo
powershell -ExecutionPolicy Bypass -File .\odoo.ps1 start
```
بار اول دانلود ایمیج‌ها بسته به اینترنت چند دقیقه طول می‌کشد.

۳. در مرورگر `http://localhost:8069` را باز کنید. صفحه‌ی ساخت پایگاه داده می‌آید:

| فیلد | مقدار |
|---|---|
| Master Password | `veron-trial-change-me` (همان که در `config/odoo.conf` است) |
| Database Name | `trial` |
| Email | نام کاربری مدیر، مثلاً `admin` |
| Password | رمز مدیر |
| Language | **Persian / فارسی** |
| Country | **Iran** |
| Demo data | اگر می‌خواهید با داده‌ی نمونه ببینید، تیک بزنید |

۴. وارد شوید. از منوی «برنامه‌ها» (Apps) ماژول‌ها را نصب کنید، مثلاً فروش، خرید، انبار، حسابداری و CRM.

## ماژول نمونه‌ی خودمان (`addons/veron_base`)
یک ماژول کوچک که نشان می‌دهد برنامه‌نویسی روی Odoo چطور است:

- مدل «یادداشت» با فیلدها و یک فیلد محاسبه‌شده؛
- فهرست و فرم؛
- دکمه‌ی «انجام شد»؛
- منوی ERP-VERON.

**نصب:** «برنامه‌ها» ← «به‌روزرسانی فهرست برنامه‌ها» ← جست‌وجوی `ERP-VERON` ← «نصب».

## پایه‌ی ایرانی (`addons/veron_core`)
پایه‌ی هر نصب ERP-VERON، که `veron_accounting` و `veron_apps` روی آن ساخته شده‌اند و با آن‌ها خودکار نصب می‌شود:

- **تاریخ شمسی همه‌جا:** فهرست‌ها، فرم‌ها، تقویم انتخاب تاریخ و صفحه‌ی «گاهشمار»، با هفته، ماه و سال شمسی. چاپ‌ها و
  ایمیل‌ها هم شمسی‌اند. تاریخ را می‌شود شمسی تایپ کرد (مثلاً `1405/09/15` یا با رقم فارسی). گروه‌بندی و نمودارها بر
  اساس ماه، فصل و سال شمسی‌اند: «آبان 1405» یعنی ۱ تا ۳۰ آبان، نه ماه میلادی. در پایگاه داده تاریخ‌ها همان میلادی
  می‌مانند.
  - فیلترهای تاریخ نوار جستجو (ماه، فصل، سال) شمسی‌اند و همان بازه‌ی شمسی را جستجو می‌کنند؛ گروه‌بندی هفتگی «هفته 32 1405».
  - نمای سالانه‌ی گاهشمار (مثلاً مرخصی‌ها) دوازده ماه شمسی است؛ در نمای هفتگی «هفته 32».
  - داده‌ی نمونه‌ای که Odoo در صفحه‌ی خالی نشان می‌دهد هم فارسی است.
  - وب‌سایت و پورتال مشتری هم تاریخ شمسی دارند.
- **تعطیلات رسمی:** تعطیلات شمسی (نوروز، ۱۲ و ۱۳ فروردین، ۱۴ و ۱۵ خرداد، ۲۲ بهمن، ۲۹ اسفند) هر سال خودکار برای امسال و
  سال بعد ثبت می‌شوند، و تعطیلات قمری ۱۴۰۵ که تاریخ رسمی‌شان معلوم است. تعطیلات قمری بقیه‌ی سال‌ها با رؤیت ماه تعیین
  می‌شوند و باید از تقویم رسمی، دستی در «مرخصی ← پیکربندی ← روزهای تعطیل عمومی» وارد شوند.
- **تنظیمات ایران:** زبان فارسی با شروع هفته از شنبه، ریال بی‌اعشار برای شرکت و لیست‌های قیمت، ساعت تهران برای همه‌ی
  کاربران، و هفته‌ی کاری ۴۴ ساعته (شنبه تا چهارشنبه ۸ تا ۱۷، پنجشنبه ۸ تا ۱۲). روی پایگاه داده‌ای که از قبل ساخته شده
  هم با هر به‌روزرسانی اعمال می‌شود. شرکتی که سند حسابداری دارد، ارز فعلی‌اش را نگه می‌دارد.
- **داشبوردها:** تاریخ‌ها و ماه‌های نمودارها شمسی، مبلغ‌ها ریالی، و متن‌هایی که Odoo ترجمه نمی‌کند (عنوان محورها،
  عنوان‌های داخل نمودارها) فارسی. داشبورد برنامه‌ای که هنوز داده ندارد، به جای نمونه‌ی انگلیسیِ دلاری Odoo، خودش با
  صفر نشان داده می‌شود. فیلتر دوره‌ی بالای داشبورد ماه، فصل و سال شمسی دارد و عددهای بزرگ «150 میلیون» نوشته می‌شوند،
  نه 150m.
- **شماره‌ی اسناد و فاکتورها با سال شمسی:** «فروش/1405/0001» که با نوروز از نو شروع می‌شود؛ سال مالی تا پایان اسفند؛
  کد دفترها فارسی و کوتاه («فروش»، «خرید»، «بانک»...).
- **ترجمه:** حدود ۲۸۰۰ عبارت ماژول‌های OCA که فارسی نداشتند (خدمات در محل، امضا، اشتراک، قرارداد، دارایی ثابت،
  گزارش‌ساز مالی، کنترل کیفیت، صفحه‌گسترده، تطبیق بانک و ...)، در `veron_core/i18n_modules`. فقط جاهای خالی را پر
  می‌کند؛ ترجمه‌ی خود ماژول یا ترجمه‌ای که دستی اصلاح شده دست نمی‌خورد. پیام‌های داخل کد این ماژول‌ها (خطاها و
  هشدارها) هم از همین فایل‌ها فارسی می‌شوند. چند ترجمه‌ی نامناسب خود Odoo (مثل «ربع» به جای «فصل») در
  `veron_core/i18n_overrides.json` عوض شده‌اند. نام برنامه‌های OCA در صفحه‌ی «برنامه‌ها» هم فارسی است.
- **نام ERP-VERON** به جای Odoo در عنوان پنجره، صفحه‌ی ورود و پایین صفحه‌ها. پیوندهای مستندات و پشتیبانی Odoo از منوی
  کاربر برداشته شده‌اند و برنامه‌های پولی در فهرست «برنامه‌ها» نشان داده نمی‌شوند.

**نصب یا به‌روزرسانی روی پایگاه داده‌ی فعلی:**
```powershell
powershell -ExecutionPolicy Bypass -File .\odoo.ps1 install veron_apps trial
```
بعد صفحه را با Ctrl+F5 تازه کنید.

## صفحه‌ی اصلی با آیکون برنامه‌ها (`web_responsive`)
صفحه‌ی تمام‌صفحه‌ی برنامه‌ها مال نسخه‌ی پولی است و نسخه‌ی رایگان فقط یک منوی کشویی دارد. ماژول رایگان
`web_responsive` از OCA (مجوز LGPL، نسخه‌ی ۱۹، از مخزن OCA/web که با `.\odoo.ps1 oca` گرفته می‌شود) همان صفحه را
برمی‌گرداند: با کلیک روی آیکون بالای صفحه، همه‌ی برنامه‌ها با آیکون و یک جست‌وجوی منو باز می‌شوند. روی گوشی هم
ظاهر را مرتب‌تر می‌کند.

آیکون ۹ مربع مثل نسخه‌ی پولی باز و بسته می‌کند: کلیک اول صفحه‌ی برنامه‌ها را باز می‌کند و کلیک دوم (یا Esc) به
صفحه‌ای که باز بود برمی‌گرداند. برای رفتن به یک برنامه، روی آیکون خود آن برنامه بزنید.

با `veron_apps`، بعد از ورود همیشه همین صفحه‌ی برنامه‌ها باز می‌شود، نه اولین برنامه‌ی منو. برای کاربری که در
«تنظیمات ← کاربران» یک «اقدام خانه» برایش تعیین شده باشد، همان صفحه باز می‌شود.

**نصب، ساده‌ترین راه:** نام پایگاه داده‌ی خودتان را به جای `trial` بنویسید:
```powershell
powershell -ExecutionPolicy Bypass -File .\odoo.ps1 install web_responsive trial
```

**نصب از داخل Odoo:**
1. حالت توسعه‌دهنده را روشن کنید. «تنظیمات» ← پایین صفحه ← «فعال‌سازی حالت توسعه‌دهنده»، یا آدرس
   `http://localhost:8069/odoo?debug=1`. بدون آن، گزینه‌ی «به‌روزرسانی فهرست برنامه‌ها» دیده نمی‌شود.
2. «برنامه‌ها» ← «به‌روزرسانی فهرست برنامه‌ها».
3. فیلتر «برنامه‌ها» را از کادر جست‌وجو بردارید (این یک ماژول است، نه برنامه).
4. `Web Responsive` را جست‌وجو کنید و «فعال‌سازی» را بزنید.

**اگر دوباره منوی کشویی ساده آمد:** یعنی Odoo پوشه‌ی `oca\web` را نمی‌بیند. این را بزنید و صفحه را با Ctrl+F5 تازه کنید:
```powershell
docker compose up -d --force-recreate odoo
```
علتش این است که `docker compose restart` و `start` همان کانتینر قدیمی را روشن می‌کنند و تغییرهای تازه‌ی
`docker-compose.yml` (مثل پوشه‌ی `oca`) را نمی‌بینند. `odoo.ps1` از این نسخه به بعد همیشه با `up` روشن می‌کند و هر
مخزن OCA ِ جاافتاده را هم خودش می‌گیرد.

**تم‌های فروشگاه Odoo:** تم‌های فروشگاه apps.odoo.com را هم می‌شود به همین شکل نصب کرد: فایل zip را دانلود و در
پوشه‌ی `addons` باز کنید. پیش از دانلود سه چیز را ببینید:
- نسخه‌ی **۱۹** را انتخاب کرده باشید؛
- **Community** را پشتیبانی کند؛
- **مجوزش** LGPL باشد، یا اگر OPL است، قیمت و اجازه‌ی استفاده برای مشتری را بدانید.

## حسابداری کامل بدون نسخه‌ی پولی (`addons/veron_accounting`)
برنامه‌ی «حسابداری» Odoo پولی است. ماژول `veron_accounting`، به کمک ماژول‌های رایگان OCA، کمبودهای «صدور فاکتور»
رایگان را پر می‌کند:

| بخش | از کجا |
|---|---|
| منوهای کامل حسابداری (سند روزنامه، جدول حساب‌ها، بازبینی) برای مدیر حسابداری | خود ماژول (در نسخه‌ی رایگان پشت یک تنظیم فنی پنهان است) |
| دفتر کل، دفتر روزنامه، تراز آزمایشی، آیتم‌های باز، مانده‌ی سررسید، گزارش ارزش افزوده، با خروجی PDF و Excel | OCA `account_financial_report` |
| تطبیق بانک و ورود صورت‌حساب بانک از فایل | OCA `account_reconcile_oca`، `account_statement_import_file` |
| دارایی ثابت و استهلاک | OCA `account_asset_management` |
| گزارش‌ساز ترازنامه و سود و زیان | OCA `mis_builder` |
| جدول حساب‌های ایرانی، بانک‌های ایرانی، استان‌ها و شهرها | OCA `l10n_ir_account`، `l10n_ir_states` |
| حساب‌های پیش‌فرض درآمد، هزینه، تسعیر ارز، کسری و اضافه صندوق و موجودی (جدول OCA آن‌ها را به روش Odoo 18 می‌دهد و در Odoo 19 بدون آن‌ها هیچ فاکتوری ثبت نمی‌شد) | خود ماژول |

**نصب:**
```powershell
cd D:\majidehtesham4
git pull
cd odoo
powershell -ExecutionPolicy Bypass -File .\odoo.ps1 oca
powershell -ExecutionPolicy Bypass -File .\odoo.ps1 install veron_accounting trial
```
- `oca` مخزن‌های OCA را (حدود ۳۰۰ مگ) در پوشه‌ی `oca` می‌گیرد. بعدها همین دستور به‌روزشان می‌کند.
- به جای `trial` نام پایگاه داده‌ی خودتان را بنویسید.

**جدول حساب‌های ایرانی:** اگر در شرکت هنوز هیچ سندی ثبت نشده باشد، موقع نصب خودکار جایگزین جدول حساب‌های عمومی می‌شود.
اگر سند ثبت شده باشد، جدول فعلی می‌ماند، چون Odoo تعویض جدول حساب‌ها را بعد از ثبت سند اجازه نمی‌دهد. در آن صورت
یک پایگاه داده‌ی تازه بسازید (`.\odoo.ps1 createdb erp`) و `veron_accounting` را روی آن نصب کنید.

**هنوز کامل نشده:**
- چک، سامانه‌ی مؤدیان و حقوق ایرانی در مراحل بعد ساخته می‌شوند.

## همه‌ی برنامه‌ها به جای نسخه‌ی پولی (`addons/veron_apps`)
برنامه‌هایی که در فهرست «برنامه‌ها» دکمه‌ی «ارتقا» دارند، مال نسخه‌ی پولی‌اند و در نسخه‌ی رایگان نصب نمی‌شوند. ماژول
`veron_apps` به جای هر کدام که جایگزین رایگان دارد، آن را نصب می‌کند، همه با یک دستور:

```powershell
cd D:\majidehtesham4
git pull
cd odoo
powershell -ExecutionPolicy Bypass -File .\odoo.ps1 install veron_apps trial
```
به جای `trial` نام پایگاه داده‌ی خودتان را بنویسید. بار اول ماژول‌های OCA تازه را هم می‌گیرد؛ نصب چند دقیقه طول
می‌کشد. اگر `veron_accounting` را قبلاً نصب کرده‌اید، برای نام‌های فارسی تازه این را هم بزنید:
`.\odoo.ps1 update veron_accounting trial`

| برنامه‌ی پولی | جایگزین رایگان | در منو |
|---|---|---|
| حسابداری | `veron_accounting` (بالا) و بودجه (`account_budget_oca`) | حسابداری |
| اسناد | OCA `dms` | اسناد |
| امضا | OCA `sign_oca` | امضای الکترونیک |
| پشتیبانی (Helpdesk) | OCA `helpdesk_mgmt`، با نوع تیکت و SLA | پشتیبانی |
| خدمات در محل | OCA `fieldservice` | خدمات در محل |
| اشتراک | OCA `subscription_oca` و قراردادها (`contract`) | اشتراک‌ها |
| دانش | OCA `document_page` | دانش |
| حقوق و دستمزد | OCA `payroll` (پایه؛ قانون کار ایران بعداً) | حقوق و دستمزد |
| کیفیت | OCA `quality_control_oca` | کنترل کیفیت |
| صفحه‌گسترده | OCA `spreadsheet_oca` | صفحه‌گسترده |
| برنامه‌ریزی | نمای خط زمانی پروژه (`project_timeline`) | پروژه |
| نوبت‌دهی | OCA `resource_booking`: نوبت با زمان‌های آزاد کارکنان و امکانات؛ مشتری در پورتال با تقویم شمسی زمان را انتخاب می‌کند | نوبت‌ها |
| تلفن (VoIP) | OCA `voip_oca`: تماس از داخل برنامه؛ مرکز تلفن اینترنتی (Issabel، Asterisk و ...) لازم دارد | تنظیمات ← تلفن اینترنتی |
| کارکرد | کارکرد خود Odoo با دکمه‌ی شروع و پایان کار (`hr_timesheet_time_control`) | برگه ساعت کارکرد |

برنامه‌های پولی که هنوز جایگزین رایگان برای Odoo 19 ندارند: اجاره، تأییدیه‌ها، ارزیابی عملکرد، بارکد، PLM،
استودیو، اتوماسیون مارکتینگ، شبکه‌های اجتماعی، IoT و واتس‌اپ. این‌ها در فهرست «برنامه‌ها» همچنان «ارتقا»
دارند؛ آن دکمه به خرید نسخه‌ی پولی می‌رود و نباید زده شود. هر کدام را که لازم شد، خودمان می‌سازیم (`MODULES.md`).

## ماژول‌های OCA
مخزن‌هایی که استفاده می‌شوند در `oca-repos.txt` فهرست شده‌اند، همه روی شاخه‌ی 19.0. پوشه‌ی `oca` در گیت این پروژه
نیست و با `.\odoo.ps1 oca` گرفته و به‌روز می‌شود. برای افزودن یک مخزن دیگر:
1. نامش را به `oca-repos.txt` اضافه کنید.
2. مسیرش را به `addons_path` در `config/odoo.conf` اضافه کنید.
3. `.\odoo.ps1 oca` را اجرا کنید.

## برنامه‌نویسی
- همه‌ی کدهای شما در پوشه‌ی `addons` است، روی خود ویندوز. خود Odoo تغییر داده نمی‌شود.
- هر ماژول یک پوشه است با `__manifest__.py`. نمونه‌اش `veron_base` است.
- **تغییر در فرم‌ها و گزارش‌ها (XML):** با تازه‌کردن صفحه دیده می‌شود (حالت `--dev=xml`).
- **تغییر در کد پایتون یا فیلدها:** ماژول را به‌روز کنید:
  ```powershell
  powershell -ExecutionPolicy Bypass -File .\odoo.ps1 update veron_base trial
  ```
- **برای مطالعه‌ی کد خود Odoo** (اختیاری، حدود ۱ گیگ)، فقط همان ورژن را بگیرید، بیرون از این پوشه:
  ```powershell
  git clone --depth 1 --branch 19.0 https://github.com/odoo/odoo.git D:\odoo-src
  ```
  آن را فقط برای خواندن و تکمیل خودکار در VS Code استفاده کنید و چیزی در آن تغییر ندهید.

## دستورهای روزمره
```powershell
.\odoo.ps1 start    # روشن کردن (بار اول ماژول‌های OCA را هم می‌گیرد)
.\odoo.ps1 oca      # گرفتن یا به‌روز کردن ماژول‌های OCA
.\odoo.ps1 stop     # خاموش کردن (داده‌ها می‌مانند)
.\odoo.ps1 logs     # دیدن گزارش اجرا و خطاها
.\odoo.ps1 install veron_apps trial   # نصب یک ماژول (این یکی: همه‌ی برنامه‌ها)
.\odoo.ps1 update veron_base trial   # به‌روز کردن ماژول بعد از تغییر کد
.\odoo.ps1 remove   # حذف کامل (پوشه‌ی addons می‌ماند)
```

## حذف کامل و برگرداندن فضا
۱. `.\odoo.ps1 remove` را اجرا کنید (تأیید با `yes`).

۲. Docker Desktop فضای آزادشده را خودش به ویندوز پس نمی‌دهد. برای برگرداندنش:
- Docker Desktop را ببندید (Quit).
- در PowerShell با دسترسی Administrator این را بزنید:
  ```powershell
  wsl --shutdown
  ```
- در Docker Desktop: Settings ← Resources ← Disk image ← «Clean / Purge data» یا «Compact».

  نسخه‌های جدید Docker Desktop گزینه‌ی کم‌کردن حجم دیسک را دارند؛ در نسخه‌های قدیمی‌تر می‌شود فایل
  `docker_data.vhdx` را با `diskpart` کوچک کرد. اگر لازم شد، روشش را قدم‌به‌قدم می‌گویم.

## چند نکته
- **تاریخ‌ها:** خود Odoo 19 تقویم شمسی ندارد (ماه شمسی را با سال و روز میلادی قاطی می‌کند)؛ `veron_core` درستش می‌کند.
- **حساب‌ها و مالیات ایران:** دفتر حساب‌های ایرانی، چک و مالیات بر ارزش افزوده‌ی ایران در Odoo آماده نیست و باید ماژولش
  ساخته یا پیدا شود. کارهای ERP-VERON (نمایشگاه خودرو، اقساط، سرمایه‌گذاران) هم در Odoo وجود ندارد.
- **Odoo 20 هم منتشر شده،** ولی تازه است. برای بررسی، ۱۹ پایدارتر است. ورژن در `docker-compose.yml` ثابت شده
  (`odoo:19.0`) و فقط با عوض کردن همان خط تغییر می‌کند.
- **رمزها:** این نصب فقط برای آزمایش است. پیش از وارد کردن اطلاعات واقعی، Master Password در `config/odoo.conf` و
  رمز پایگاه داده را عوض کنید.
