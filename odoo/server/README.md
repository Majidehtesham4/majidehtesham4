# راه‌اندازی ERP-VERON روی سرور، برای مشتری‌ها

یک Odoo برای همه‌ی مشتری‌ها. هر مشتری پایگاه داده‌ی جدای خودش را دارد و با آدرس خودش، مثلاً `https://erp.automodiran.ir`،
وارد می‌شود. هر آدرس فقط پایگاه داده‌ی خودش را باز می‌کند و فهرست پایگاه داده‌ها و صفحه‌ی مدیریتشان روی اینترنت بسته است.

```
مرورگر مشتری ── https ──▶ Caddy (پورت 80 و 443، گواهی HTTPS خودکار)
                              ▼
                          Odoo 19 + ماژول‌های ما ──▶ PostgreSQL: یک پایگاه داده برای هر آدرس
```

## ۱. سرور
سه راه هست. همین بسته روی هر سه یکسان نصب می‌شود.

| | سرور ابری (VPS) | کامپیوتر خودتان | کامپیوتر خودتان در دیتاسنتر (Colocation) |
|---|---|---|---|
| هزینه | ماهانه، ثابت | خرید یک‌باره + IP ثابت | خرید یک‌باره + اجاره‌ی ماهانه‌ی جا و برق |
| برق و اینترنت | با دیتاسنتر | با شما؛ قطعی برق یا اینترنت = قطعی همه‌ی مشتری‌ها | با دیتاسنتر |
| IP ثابت | دارد | باید از شرکت اینترنت بخرید | دارد |
| خرابی سخت‌افزار | با ارائه‌دهنده | با شما | با شما |
| مناسب برای | شروع و مشتری‌های واقعی | آزمایش، نمایش به مشتری، نگه‌داشتن پشتیبان‌ها | وقتی مشتری‌ها زیاد شدند |

**کمترین مشخصات:** ۴ هسته، ۸ گیگ رم (برای کامپیوتر خودتان ۱۶ گیگ)، ۱۰۰ گیگ SSD، **Ubuntu 24.04**.
روی کامپیوتر خودتان، Ubuntu را روی یک کامپیوتر جدا نصب کنید، نه روی ویندوزی که با آن کار می‌کنید.

**کامپیوتر خودتان، پیش از هر چیز:**
- **IP ثابت عمومی** از شرکت اینترنت بخرید. بیشتر اینترنت‌های خانگی و اداری IP ثابت ندارند و از بیرون در دسترس نیستند.
- در مودم، پورت‌های **80 و 443** را به IP همین کامپیوتر بفرستید (Port Forwarding).
- **یو‌پی‌اس** بگذارید. قطعی‌های برنامه‌ریزی‌شده‌ی برق را هم در نظر بگیرید.
- سرعت **آپلود** اینترنت مهم است، چون همه‌ی مشتری‌ها از همان آپلود استفاده می‌کنند.

## ۲. دامنه
- **دامنه‌ی خودتان:** یک دامنه بگیرید، مثلاً `veron.ir`. در پنل DNS آن یک رکورد بگذارید تا هر زیردامنه به سرور بیاید:
  نوع **A**، نام `*`، مقدار **IP سرور**. بعد هر مشتری می‌شود مثلاً `automodiran.veron.ir`.
- **دامنه‌ی خود مشتری:** اگر مشتری سایت دارد، مثلاً `automodiran.ir`، در پنل دامنه‌اش یک رکورد بگذارد:
  نوع **A**، نام `erp`، مقدار **IP سرور شما**. سایت اصلی‌اش دست نمی‌خورد. آدرس ERP او می‌شود `erp.automodiran.ir`.

رکورد DNS باید **پیش از** ساختن مشتری (قدم ۴) گذاشته شده باشد، چون گواهی HTTPS برای همان آدرس گرفته می‌شود.

## ۳. نصب روی سرور (یک بار)
از ویندوز، در PowerShell، به سرور وصل شوید (IP و رمز root را ارائه‌دهنده یا خودتان موقع نصب Ubuntu دارید):
```powershell
ssh root@IP-سرور
```
بعد روی سرور:
```bash
git clone https://github.com/majidehtesham4/majidehtesham4.git /srv/veron
cd /srv/veron/odoo/server
./veron setup ایمیل-شما@example.com
```
- اگر مخزن خصوصی است، `git clone` نام کاربری گیت‌هاب و یک **توکن** (به جای رمز) می‌خواهد.
- `setup` این کارها را می‌کند:
  - Docker را نصب می‌کند و دیواره‌ی آتش را می‌بندد (فقط SSH، 80 و 443 باز می‌ماند).
  - رمزهای پایگاه داده و مدیریت را تصادفی می‌سازد و فقط روی سرور نگه می‌دارد.
  - ماژول‌های OCA را می‌گیرد، همه‌چیز را روشن می‌کند و پشتیبان‌گیری شبانه را تنظیم می‌کند.
- ایمیل برای گواهی‌های HTTPS است.
- Docker Hub به سرورهای ایران جواب نمی‌دهد. `setup` ایمیج‌ها را از آینه‌ی داخلی آروان (`docker.arvancloud.ir`) می‌گیرد.
  اگر آن در دسترس نبود، آینه‌ی دیگری را در `/etc/docker/daemon.json` بگذارید.

## ۴. هر مشتری تازه
```bash
cd /srv/veron/odoo/server
./veron new erp.automodiran.ir veron_apps "نمایشگاه اتومدیران"
```
- اول آدرس، بعد ماژول‌ها، بعد نام شرکت.
  - پیش‌فرض ماژول‌ها `veron_apps` است: همه‌ی برنامه‌ها.
  - برای یک نمایشگاه خودرو `veron_pack_showroom` را بدهید، بسته‌ی همان کسب‌وکار.
- چند دقیقه طول می‌کشد. در آخر آدرس، نام کاربری `admin` و یک **رمز تصادفی** را نشان می‌دهد.
- رمز فقط همان لحظه نشان داده می‌شود و جایی ذخیره نمی‌شود. آن را به مشتری بدهید تا بعد از ورود عوضش کند.
- رمز تازه، اگر گم شد: `./veron password erp.automodiran.ir`

کارمندان مشتری را مدیرِ خود مشتری از «تنظیمات ← کاربران» می‌سازد و برایشان نقش تعیین می‌کند.

## حالت محلی: داخل شبکه‌ی شرکت، بدون دامنه
برای وقتی که ERP فقط داخل شبکه‌ی خود شرکت (همان مودم و شبکه‌ی اداره) استفاده می‌شود و دامنه و IP ثابت اینترنتی لازم نیست.
همه‌ی کامپیوترها و گوشی‌هایی که به همان شبکه وصل‌اند با آدرس IP سرور وارد می‌شوند؛ از بیرون شبکه در دسترس نیست.

۱. Ubuntu 24.04 را روی یک کامپیوتر جدا نصب کنید و آن را با کابل به مودم وصل کنید.
۲. در صفحه‌ی مودم، برای این کامپیوتر **IP ثابت داخلی** رزرو کنید (DHCP Reservation)، مثلاً `192.168.1.10`.
   اگر IP عوض شود، آدرس ERP هم عوض می‌شود.
۳. روی سرور:
```bash
git clone https://github.com/majidehtesham4/majidehtesham4.git /srv/veron
cd /srv/veron/odoo/server
./veron setup local
./veron new 192.168.1.10 veron_apps "نام شرکت"
./veron ca
```
- `setup local` ایمیل نمی‌خواهد و پورت‌های 80 و 443 را فقط برای شبکه‌ی داخلی (‎192.168.x.x، ‎10.x.x.x، ‎172.16-31.x.x) باز می‌کند.
- `new` با IP سرور، مثل حالت اینترنتی پایگاه داده و رمز تصادفی مدیر را می‌سازد. آدرس: `https://192.168.1.10`
- گواهی HTTPS را خود سرور امضا می‌کند. `ca` فایل `veron-root.crt` را می‌سازد. آن را **یک بار روی هر کامپیوتر و گوشی** نصب
  کنید تا مرورگر هشدار ندهد؛ دوربین برای بارکد و نصب برنامه روی گوشی (PWA) هم فقط با HTTPS کار می‌کنند.
  - ویندوز: فایل را باز کنید ← Install Certificate ← Local Machine ← Trusted Root Certification Authorities
  - اندروید: تنظیمات ← امنیت ← رمزگذاری و اعتبارنامه‌ها ← نصب گواهی ← گواهی CA
  - آیفون: فایل را باز کنید و نمایه را نصب کنید، بعد تنظیمات ← عمومی ← درباره ← تنظیمات اعتماد گواهی
- **پشتیبان روی دیسک دوم:** یک دیسک بیرونی وصل کنید و پوشه‌اش را در `.env` بنویسید، مثلاً `BACKUP_COPY=/mnt/backup`.
  از آن به بعد هر پشتیبان یک نسخه هم آنجا می‌رود. در حالت محلی این مهم‌تر است، چون سرور و پشتیبانش در یک ساختمان‌اند.
- بعدها اگر خواستید از بیرون هم در دسترس باشد، همین سرور با دامنه و IP ثابت به حالت اینترنتی می‌رود: `MODE=internet` و
  `ACME_EMAIL` را در `.env` بگذارید، پورت‌ها را در دیواره‌ی آتش باز کنید و برای دامنه `./veron new` بزنید.

## ۵. کارهای روزمره
```bash
./veron list      # آدرس همه‌ی مشتری‌ها
./veron backup    # پشتیبان همین حالا (هر شب ساعت ۲:۳۰ هم خودکار)
./veron update    # نسخه‌ی تازه: پشتیبان، git pull، ماژول‌های OCA، به‌روزرسانی همه‌ی مشتری‌ها
```

**پشتیبان‌ها** در پوشه‌ی `backups` هستند، برای هر روز یک پوشه. ۱۴ روز آخر نگه داشته می‌شود. برای هر مشتری دو فایل:
پایگاه داده (`.dump`) و فایل‌های پیوست (`.files.tar.gz`).

یک نسخه را **بیرون از سرور** هم نگه دارید. اگر سرور خراب شود، پشتیبانِ روی خودش هم از دست می‌رود. مثلاً از ویندوز:
```powershell
scp -r root@IP-سرور:/srv/veron/odoo/server/backups D:\veron-backups
```

## نکته‌ها
- پیش از `update` روی سرور مشتری‌ها، نسخه‌ی تازه را روی Odoo آزمایشی خودتان امتحان کنید.
- رمزهای سرور در `.env` و `config/odoo.conf` هستند و در گیت نمی‌روند. از این دو فایل هم یک نسخه جای امن نگه دارید.
- صفحه‌ی مدیریت پایگاه داده‌های Odoo روی اینترنت بسته است. ساختن، پشتیبان و رمز فقط با `./veron` روی خود سرور انجام می‌شود.
